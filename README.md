# strm-scraper

[![构建镜像](https://github.com/3548784-netizen/strm-scraper/actions/workflows/docker.yml/badge.svg)](https://github.com/3548784-netizen/strm-scraper/actions/workflows/docker.yml)
[![Docker Hub](https://img.shields.io/badge/docker%20hub-3548784%2Fstrm--scraper-2496ED)](https://hub.docker.com/r/3548784/strm-scraper)
[![镜像大小](https://img.shields.io/docker/image-size/3548784/strm-scraper?label=%E4%BD%93%E7%A7%AF)](https://hub.docker.com/r/3548784/strm-scraper)
[![GHCR](https://img.shields.io/badge/ghcr.io-3548784--netizen%2Fstrm--scraper-2496ED)](https://github.com/3548784-netizen/strm-scraper/pkgs/container/strm-scraper)

给 115 / LitePan 生成的 `.strm` 文件补上海报、背景图和 NFO 的刮削器，跑在 Docker 里。自带网页控制台，手机和电脑都能用，不用进容器改配置。

**这一版能做的事**

- **任务**：整库增量（只补缺的）/ 全量重刮、暂停·继续·取消、按状态筛选与搜索、勾选批量删除
- **文件管理**：直接浏览媒体库，勾哪个文件夹就只跑哪个；「只补缺」和「开始重刮」分开，不误伤旧图
- **自动化**：可以建多条定时任务，每条单独指定监控哪个媒体库或子文件夹、间隔多久、跑增量还是全量，到点自己扫
- **手动选帧**：自动挑的帧不满意，滚轮缩放 + 拖动画框自己选，选择记在库里，重刮也用这一帧
- **媒体服务器**：Emby / Jellyfin 多台并存，刮完自动刷新并回查有没有真的识别到图
- **配置与日志**：扫描目录、并发、海报模式、账号密码都能在网页里改；日志按级别筛选、搜索、下载

**Emby 和 Jellyfin 同时支持**：产物命名和图片比例按两家的规范来，同一份文件两边都能识别，不需要为谁单独复制一套。

```
影片目录/
├── 某影片.AVI.strm          ← 你原来的 strm，一个字都不动
├── 某影片.AVI.nfo           ← 生成
├── 某影片.AVI-poster.jpg    ← 生成（2:3 竖版海报）
├── 某影片.AVI-fanart.jpg    ← 生成（16:9 横版背景图）
└── 某影片.AVI-thumb.jpg     ← 生成（16:9 缩略图，可选）
```

## 为什么需要它

网盘挂载工具生成的 strm 只是一个文本文件，里面写着播放地址。媒体服务器读到它，能播，但拿不到任何画面信息——没有海报，没有时长，没有分辨率，列表里全是一样的灰色占位图。

这个项目做的事就是：读出 strm 里的地址 → 用 ffprobe 探测媒体信息 → 从视频里抓几帧挑最清晰的一张 → 生成海报、背景图和 NFO 放到视频旁边。

整个过程不需要下载完整视频，只读取几个关键位置的数据，所以对网盘流量几乎没有消耗。

## 特性

**支持的文件与视频格式**

| 类型 | 说明 |
|---|---|
| `.strm` | 默认只扫这个。文件里写的是播放地址（http/https/rtsp/ftp），刮削时读第一行可用链接直接抓帧 |
| 本地视频文件 | `mp4` / `mkv` / `avi` / `ts` / `m2ts` / `mov` / `wmv` / `flv` / `rmvb` / `webm` / `mpg` / `m4v` 等，在 `scan.extensions` 里加上后缀即可一起刮（默认只有 `.strm`） |
| 其它容器 | 只要容器内的 ffmpeg 能解码就能出图，扩展名可以随便加（如 `.iso` 视镜像能不能被 ffmpeg 直接读而定） |

- 判断依据是 ffmpeg / ffprobe：能探测到时长和画面就能抓帧，探测不到会写明确原因（404、403、超时、编码不支持等）
- 扩展名不区分大小写，`片名.MKV` 和 `片名.mkv` 一视同仁；产物按同名规则生成，Emby / Jellyfin 都能直接认
- 扫不到的目录（隐藏目录、`@eaDir`、`__pycache__`、`$RECYCLE.BIN`）会被跳过，避免重复处理群晖缩略图

**抓帧**

- 按片长比例采样 5 个时间点，用边缘检测方差挑出最清晰的一帧，不是固定截中间那张
- 不满意可以在网页上手动选帧，指定哪一秒出图，选择会被记住
- 快速跳转失败时自动退回解码定位，网络源不支持 Range 请求也能出图
- 自动过滤纯黑帧和色块帧

**图片规格（符合 Emby / Jellyfin 要求）**

| 产物 | 比例 | 默认尺寸 | 文件名 | 用途 |
|---|---|---|---|---|
| 海报 | 2:3 | 1000×1500 | `<名称>-poster.jpg` | 媒体库网格封面 |
| 背景图 | 16:9 | 1920×1080 | `<名称>-fanart.jpg` | 详情页背景 / backdrop |
| 缩略图 | 16:9 | 1000×562 | `<名称>-thumb.jpg` | Emby 列表视图（可选） |

比例不对会被媒体服务器拉伸或裁切，比不显示更难发现，所以配置里的尺寸一律按比例校正，偏了会在日志里明确告警。

海报有三种生成方式：`crop`（中心裁切铺满 2:3，默认——横版视频也整张铺满，和 PC 版刮削器一致）、`blur`（模糊背景 + 完整画面居中，横版视频上下留两条背景，主体不丢）、`gradient`（用画面边缘平均色做渐变背景，最干净）。

**处理**

- 多任务并发，单条超时隔离，一条视频卡住不影响整轮
- 增量模式只处理缺失项，已有产物不重复抓帧
- 失败原因写进状态库，网页上直接看到「连接被拒绝」「地址返回 404」这类具体原因

**媒体服务器联动**

- 同时配置多台 Emby / Jellyfin，刮完自动让它们重建图片缓存
- 三种认证头依次尝试（`Authorization: MediaBrowser`、`X-Emby-Token`、`?api_key=`），适配不同版本和打包方式
- 刷新参数同时写进 JSON body 和 URL query：Jellyfin 12.x 只认 body，Emby 对 query 更稳
- 刷新后回查一遍，确认媒体服务器真的识别到了图，没识别上会直接把文件名打出来

**登录**

- 控制台默认要登录，默认账号 `admin` / `admin`，登录后在网页上就能改用户名和密码
- 密码加盐哈希存在 `config/auth.json`，文件里看不到明文；改完密码旧会话立即失效
- 同一 IP 连续 5 次密码错误锁 5 分钟；确实不需要可以 `web.auth.enabled: false` 关掉

**日志**

- 控制台 + 滚动文件 + 网页实时三路输出
- 主日志记全量，`errors-*.log` 只记 WARNING 及以上，排查不用在进度里翻
- 网页上按级别、关键字筛选，一键下载，也能看原始文件末尾
- `--doctor` 自检一次查完 ffmpeg、目录、状态库、日志、服务器连通性

## 快速开始

镜像同时发布在两个仓库，内容完全一致，挑能拉快的那个用：

```
3548784/strm-scraper:latest                              # Docker Hub，国内一般更快
ghcr.io/3548784-netizen/strm-scraper:latest              # GitHub 容器仓库
```

两个都不需要登录，直接匿名拉取。`latest` 跟 `main` 分支同步，每次推送自动重建。

### 方式一：拉现成镜像（推荐）

建个目录放配置，把下面内容存成 `docker-compose.yml`：

```bash
mkdir -p /vol1/1000/docker/strm-scraper && cd /vol1/1000/docker/strm-scraper
```

```yaml
services:
  strm-scraper:
    image: 3548784/strm-scraper:latest   # 拉不动就换成 ghcr.io/3548784-netizen/strm-scraper:latest
    container_name: strm-scraper
    restart: unless-stopped
    ports:
      - "6666:6666"
    volumes:
      - ./config:/config                    # 配置目录，必须（配置、账号、状态库、日志都在这）
      - /vol1/1000/LitePan/strm:/media      # 媒体库，可映射多个
      # - /vol1/1000/另一个媒体库:/media2   # 再挂一个库，同时把 /media2 加进 scan.roots
    environment:
      TZ: Asia/Shanghai
```

```bash
docker compose up -d
```

飞牛 / 群晖这类有图形界面的 NAS，直接在 Docker 应用的「项目」里粘贴同样的内容启动即可。完整步骤见 [`docs/DEPLOY.md`](docs/DEPLOY.md)。

### 方式二：从源码构建

改代码或者想自己打镜像时用这条。镜像在 `main` 每次推送后自动重建，源码构建和拉取的效果一致。

```bash
git clone https://github.com/3548784-netizen/strm-scraper.git
cd strm-scraper
```

改 `docker-compose.yml` 里的挂载路径，把左边换成你自己的 strm 目录：

```yaml
volumes:
  - ./config:/config                    # 配置目录，必须
  - /vol1/1000/LitePan/strm:/media      # 媒体库，可映射多个
```

然后：

```bash
docker compose up -d --build
```

### 打开控制台

浏览器打开 `http://你的NAS地址:6666`，第一次会跳到登录页：

```
用户名 admin    密码 admin
```

登录后建议立刻在右上角「**账号**」里改掉，改完其他设备上的登录全部失效。

首次运行会全量扫一遍所有 strm，之后自动转成增量模式，只补新文件和缺图。跑一轮的耗时主要取决于视频数量和网盘响应速度，300 个视频大约 20~40 分钟。

### 更新到新版本

`main` 有新提交时镜像会自动重建，NAS 上重新拉一次即可：

```bash
docker compose pull && docker compose up -d
```

升级后这几项会自动处理，不用手动改配置：

- 旧版默认的海报模式 `blur`（横版视频缩在中间、上下两条深色背景）会自动改成 `crop`，横版视频也铺满整张 2:3。已经生成的旧海报不会自己重画，到「文件管理」勾上目录点「开始重刮」就会按新模式覆盖；喜欢留白效果的可以在「设置 → 刮削与图片」里改回 `blur`。
- 旧版的 `scan.interval_minutes` 会转成一条「全部媒体库」自动化任务，之后在「自动化」页里管。
- 仍然是旧默认值的提速项会自动改掉（每个都会在启动日志里写一条「配置调整：…」）：`scrape.frames` 5 → 2、`scan.timeout` 240 → 30、`scan.probe_timeout` 20 → 8。自己调过的值一律不动。

配置、状态库、日志都在 `./config` 里，更新不会丢，已生成的图片也不会重刮。

## 配置

首次启动会自动生成 `config/config.yaml`，改完重启容器生效。也可以全部用环境变量，用 `WS_` 前缀，嵌套字段用双下划线：

```yaml
WS_SCAN__CONCURRENCY=4
WS_SCAN__INTERVAL_MINUTES=360
WS_LOG__LEVEL=DEBUG
```

常用几项：

| 配置 | 说明 | 默认 |
|---|---|---|
| `scan.roots` | 要扫描的目录（容器内路径） | `/media` |
| `scan.mode` | `auto` 首次全量之后增量 / `full` 每次全量 / `incremental` 只补缺失 / `manual` 只手动 | `auto` |
| `scan.interval_minutes` | 旧版的全局定时间隔（分钟）。升级后会自动转成一条「全部媒体库」自动化任务，平时在网页「自动化」页里管理 | `0` |
| `scan.schedule_mode` | 上面那条兼容任务的执行方式：`incremental` 只补缺失 / `full` 整库重刮并覆盖 | `incremental` |
| `scan.autostart` | 容器启动后先自动跑一轮 | `false` |
| `scan.concurrency` | 并发数。网盘按**瞬时并发**限流，3 最稳，5 以上容易撞 503/504 | `3` |
| `scan.timeout` | 单个时间点抓一帧的超时（秒），超过就放掉重排 | `30` |
| `scan.probe_timeout` | 探测超时，strm 地址失效时靠它快速失败 | `8` |
| `scrape.frames` | 采样帧数。从 `frame_positions` 里**按比例均匀取**，2 帧 = 列表两端 | `2` |
| `scrape.frame_positions` | 采样位置（按片长比例），列表越长可挑的档位越细 | `[0.15, 0.30, 0.45, 0.60, 0.75]` |
| `scrape.poster.mode` | `crop` 中心裁切铺满 / `blur` 模糊背景补边 / `gradient` 渐变补边 | `crop` |
| `scrape.thumb.enabled` | 是否额外生成 16:9 缩略图 | `false` |
| `scrape.overwrite` | `missing` 只补缺失 / `always` 每次覆盖 | `missing` |
| `servers[]` | 媒体服务器列表，见下一节 | 空 |
| `web.auth.enabled` | 控制台是否要登录 | `true` |
| `web.auth.session_hours` | 登录保持多少小时 | `168` |
| `log.level` / `log.dir` | 日志级别与目录 | `INFO` / `/config/logs` |

完整项见 [`config.example.yaml`](config.example.yaml)，每项都有注释。

## Emby / Jellyfin 联动

不配也能用，只是图片生成后要自己在服务器上点一次刷新——**Jellyfin 不会自动重读图片缓存**，Emby 一般会自动发现。

想让刮完自动生效，在 `servers` 里加一台或多台：

```yaml
servers:
  - name: jellyfin
    type: jellyfin            # jellyfin / emby / auto（自动识别）
    enabled: true
    url: "http://192.168.1.10:8096"
    api_key: "控制台 → API 密钥 → 新建"
    refresh_after: true       # 刮完自动重建图片缓存
    verify_after: true        # 刷新后回查，确认图被识别
    path_map:
      /media: /vol1/1000/LitePan/strm   # 容器路径 → 服务端看到的路径

  - name: emby
    type: emby
    enabled: true
    url: "http://192.168.1.11:8096"
    api_key: "Emby 控制台 → 高级 → API 密钥"
    path_map:
      /media: /vol1/1000/LitePan/strm
```

`path_map` 不能省。容器里是 `/media`，服务端可能是 `/vol1/1000/...`，不做前缀替换就永远匹配不上条目。日志里如果出现「N 个文件找不到对应条目」，会同时打印两边路径的对照，照着改就行。

网页上的「媒体服务器」面板可以：

- 看每台的连接状态和版本
- **测试连接**：立即重连一次，不用等缓存
- **扫描媒体库**：让服务器重新扫一遍目录
- **补齐缺图**：把已刮削过的文件全部提交一次图片重建，等于以前手动点「刷新元数据 → 替换现有图片」那套操作

## 产物说明

**文件名**

跟 strm 同名，加后缀。`某影片.AVI.strm` 对应 `某影片.AVI.nfo` / `某影片.AVI-poster.jpg` / `某影片.AVI-fanart.jpg`。这套命名 Emby 和 Jellyfin 都认，而且不改动目录结构，服务器里已有的条目不会重建。

**NFO 标题**

会去掉文件名尾巴上的伪扩展名再写进 `<title>`。`流浪地球2.2023.2160p.WEB-DL.AVI` → `流浪地球2.2023.2160p.WEB-DL`。Jellyfin 里显示的标题会跟着变干净。

**NFO 内容**

Kodi / Emby 标准 `<movie>` 格式，UTF-8 无 BOM，包含时长、码率、分辨率、宽高比、帧率、音轨信息。`runtime` 和 `durationinseconds` 的单位分别是分钟和秒，两者一致。

## 网页控制台

`http://NAS:6666`

**任务列表**

- 登录后才能操作，默认账号 `admin` / `admin`
- 顶部按钮：开始任务（整库增量，只补缺的）/ 全量重刮（整库全覆盖）/ 暂停（暂停后变「继续任务」）/ 取消任务
- 状态条：状态灯、进度条、成功 / 失败 / 待处理 / 总数 / 用时
- 表格：状态、视频名称、时长、大小、海报缩略图、背景图缩略图、NFO、备注、操作
- 按状态筛选、只看失败、搜索片名或路径、分页、单条重刮 / 选帧 / 删产物
- 排序：**最近处理 / 添加时间 / 名称**，默认按「添加时间」倒序（最新入库的在最前），点当前选中的那一项翻转正序倒序
  （「按文件夹」视图下每一层都按同样的规则排）
- 每行左侧有勾选框，表头可全选当前页：选好后点「删除 ▾」——
  **仅从任务列表移除**（下次扫描会重新登记），或**移除并删除已生成的图片 / NFO**。
  媒体库里的 `.strm` 本身永远不动；正在处理的那条会自动跳过。
- **「按文件夹」视图是一棵目录树**，层级和文件管理里一层层点进去的完全一致：
  媒体库 → 分类 → 片名 → 文件。收起的分支只占一行，但下面挂着整支子树的汇总
  （条数、进度、处理中 / 待处理 / 失败），不看也知道跑到哪了。
  - 点文件夹名（或前面的三角）展开 / 收起，缩进每层 20px，文件行对在所属文件夹的名字下面
  - 默认展开顶层，以及「只有一个子目录、自己又没放视频」的中转层（`媒体库/电影/某合集` 这种没什么信息量的过道）
  - 工具栏的**展开全部 / 收起全部**一次到位；文件列表一次只顺带加载 30 个文件夹，其余的展开着、点开再拉
  - 搜索或改状态筛选时会自动展开到命中的分支，省得结果藏在收起的分支里
  - 勾选框按目录整支算：勾上层就等于勾了整支（下层显示为已选中、不能再单独点），
    删的是这一支里的全部记录；从文件管理点过来时，刚选的那一层会自动展开祖先并高亮

**暂停和取消的区别**

| 操作 | 已经在跑的任务 | 队列 | 结果 |
|---|---|---|---|
| 暂停 | 跑完当前这批再停住 | 停止派发 | 保留，继续后接着来 |
| 取消 | 无法中断，但结果作废 | 立即停止 | 状态退回待处理，下次开始重新做 |

**文件管理**

- 直接浏览扫描目录，面包屑 + 上一级，目录后面标着里面有几个 strm
- 每个文件的海报 / 背景图 / NFO 有没有、多大，一眼可见；**没有海报的格子直接写「未生成」**（悬停说明原因：还没刮削 / 上次失败 / 有 NFO 但海报不在），有海报的是缩略图，点开可放大
- **海报进度条**：列表上方一条横条，回答「这个目录还有多少张海报没生成」——已生成 / 总数、百分比、还差几个、其中几个上次失败；正在跑时补一句「正在生成 N 个…」。统计口径是本目录直接放着的 strm **加上**各子目录（递归）里的 strm，所以不点进去也知道整支的情况。文件夹行的海报列给的是同一支子树的进度（`3/12`，缺的时候是琥珀色）
- **只看未生成**：进度条右侧的开关，一点就只剩没海报的文件和还有缺口的文件夹，按钮上带数量；这时候「全选」也只勾筛出来的，点「开始刮削」就能一次补齐（已经齐的会被自动跳过，不会重刮）。全补完后开关自己收起，进度条写「全部已生成」并变绿
- 状态列按「产物在不在」判：**刮削成功 / 刮削失败 / 刮削中 / 未刮削**。任务是 ok 还是 skipped 都算刮过（skipped 只说明产物早就在了），鼠标悬停能看到三类产物各自的明细
- **文件夹也有状态**：范围是整个文件夹（含子目录，和勾选文件夹时选中的范围一致），全刮完显示「刮削成功」，一个没刮显示「未刮削」，刮了一半显示进度如「已刮 3/5」，悬停能看到总数 / 已刮 / 未刮
- 按状态筛选：**全部 / 刮削成功 / 未刮削 / 失败**，按钮上直接显示各自数量（文件和文件夹一起算）；筛选只作用于当前目录这一屏，文件夹跟着一起过滤，点「全选」也只勾筛出来的那些
- 勾选后可批量：刮削选中、删除产物、仅删 NFO；删完状态自动重置，下次开始重新生成
- 排序：按**名称 / 添加时间（文件修改时间）/ 大小**，默认按「添加时间」倒序，点当前选中项翻转正序倒序；文件夹始终排在文件前面
- **勾谁跑谁**：勾了哪个文件夹（或哪几个文件）就只跑它们，不会顺手把其它文件夹的待处理项一起拉起来；整库级的操作在任务页（开始任务 / 全量重刮）
- **开始刮削只补缺**：图片和 NFO 都齐的条目直接跳过，不重新探测、不改状态；想连旧图一起换，点紧挨着的「开始重刮」
- **开始重刮（选中）**：勾了什么就重刮什么——勾单个文件只重做这个，勾文件夹就是里面所有 strm（含子目录），海报 / 背景图 / NFO 直接覆盖；整库覆盖用任务页的「全量重刮（整库）」
- **开始文件夹海报修复（手动）**：让多层嵌套里**每一层**文件夹都有封面。Emby 和 Jellyfin 用的是同一套取图规则——目录里直接有视频，这个目录就是「影片」条目，认 `<视频名>-poster.jpg`；目录里只有子目录，它是「文件夹」条目，只认 `folder.jpg` / `poster.jpg` / `cover.jpg`，按视频名生成的海报对它完全无效。所以「媒体库/文件夹1/文件夹2/视频」这种结构下中间几层一定空着。这个动作会把选中目录、它上面到媒体库根的每一层、以及它下面每一层都补上，每层同时写 `folder.jpg` 和 `poster.jpg` 两个名字（两家客户端都能认），图片取自里层已刮好的海报。备注列标「缺海报」的层就是会出问题的层，勾上点这个按钮即可，分「只补缺的」「全部覆盖重建」两项。**正常刮削不做这件事**，扫描根本身也不会被写
- **指定用哪张图当封面**：合集类目录（「某合集/第 1 部、第 2 部…」）里，父层封面该用哪一部只有人知道，程序按名字排第一张经常猜错。点文件夹行右边的「封面」，会列出这个文件夹里所有已刮好的海报（正片海报在前、子目录里的 folder.jpg 在后，本层现有的封面不重复列），点一张再点「用这张」即可。指定关系存在状态库里，之后不管「只补缺的」还是「全部覆盖重建」都优先用它，不会再被自动挑的覆盖；「恢复自动」清掉指定。备注列会显示「海报已就绪 · 已指定」
- 只能操作 `scan.roots` 里的路径，`../` 和系统目录会被 403 挡掉

**其它面板**

- 媒体服务器：连接状态、测试连接、扫描媒体库、补齐缺图
- 运行日志：级别筛选、关键字搜索、跟随最新、看原始文件、下载主日志和错误日志
- 设置：登录账号、媒体库目录、刮削参数、Emby / Jellyfin 地址与密钥都能在网页里改

**设置页**

不用再进容器改 `config.yaml`，改完点「保存设置」就写回配置文件并立即生效：

| 区块 | 能改什么 |
|---|---|
| 登录账号 | 用户名、密码（要验证当前密码，改完其他设备重新登录） |
| 媒体库 | 扫描目录（每行一个，容器内绝对路径）、并发数、超时、扫描模式 |
| 刮削与图片 | 海报模式（crop / blur / gradient）、覆盖策略、JPEG 质量、采样帧数、生成哪几种产物 |
| 媒体服务器 | 地址、API 密钥、类型、请求超时、路径映射、刮完自动刷新 / 扫库、自签名证书 |

**自动化页**

定时扫库不在设置里了，单独一个「自动化」标签页（在「媒体服务器」和「运行日志」之间）。
一条任务 = 一个监控范围 + 一个间隔 + 一种执行方式，可以建多条：

| 能设什么 | 说明 |
|---|---|
| 任务名称 | 随便写，列表和日志里用它区分 |
| 监控范围 | 全部媒体库，或点进某个媒体库 / 子文件夹后「设为当前目录」——只刮这个目录（含子目录）里的 strm，别的目录不动 |
| 间隔 | 最小 5 分钟，最长 7 天；也有「每小时 / 6 小时 / 12 小时 / 每天」快捷选项 |
| 执行方式 | 增量：只补新文件和缺产物的；全量：范围内全部重刮并覆盖旧图 |
| 启用 / 停用 | 停用后不再自动跑，任务保留，随时再开 |

- 列表上每条任务显示监控路径、下次运行时间、上次结果和累计跑过几次，可以直接「立即执行」
- 任意时刻只跑一轮；到点时如果上一轮还没跑完，这一条自动顺延到下一轮，不会排队堆积
- 任务存在 `state.db` 里，重建容器、换镜像都还在
- 页头还有「启动后先跑一轮」全局开关（对应 `scan.autostart`），跟具体任务无关
- 保存时逐项校验，任何一项不合法整单拒绝，不会留下改了一半的配置
- API 密钥不回传明文，输入框留空表示沿用已保存的那个
- 写回的是**完整配置**，`config.yaml` 里的注释会丢失；要保留注释就直接编辑文件
- 环境变量（`WS_*`）优先级高于配置文件，两者冲突时以环境变量为准

## 手动选帧

自动选帧是按比例采样再挑最清晰的一帧，碰到片头黑场、字幕压屏、画面切镜的时候不一定合心意。文件管理或任务列表里点某一行的「选帧」，可以自己挑。

面板里能做的事：

- 打开时按片长 3%–92% 抽 12 张候选缩略图，避开片头厂标和片尾字幕
- 点缩略图直接定位；不精确就拖时间轴，或用「−1 秒 / +1 秒」微调
- 大图实时预览，确认是想要的画面再动手
- 勾选要更新的图片（海报 / 背景图 / 缩略图），一键生成，可选顺手通知媒体服务器刷新
- **画面缩放**：滚轮以指针为中心放大（1×–8×），右下角「− / 百分比 / +」同样能缩放，点百分比回到适应窗口；放大后按住空格拖（或中键拖）平移画面，取景框坐标不会跟着跑
- **自定义裁切**：画面上的裁切框固定按当前比例（海报 2:3 / 背景图 16:9），拖框内任意位置平移、拖四角缩放，比例不会走样，框也出不了画面；放大后拖空白处是平移画面，按住 Alt 拖才画新框；方向键可以逐格微调（Shift 加速），点「重置裁切框」回到居中默认大小。框外压暗、九宫格辅助线，右侧实时显示裁出来的效果
- 勾选要更新的图片后点底部「确定裁切」出图；选「整帧」时不裁切，按钮会变成「使用整帧」
- 选定的时间点会记在状态库里，文件名旁边显示「手选 12:34」；**之后重刮、开始重刮都沿用这一帧**，不会被自动采样覆盖
- 想回到自动挑帧就点「恢复自动」，现有图片不变，下次重刮重新采样

实现上的两点：

- 预览帧按「文件 + 修改时间 + 时间点 + 宽度」缓存在 `config/framecache/`，来回拖动不重复打网络；缓存 6 小时过期，最多 400 张
- 抓帧同时最多 4 路；候选缩略图在网页端改成主帧出来之后再一张张补，避免十几张缩略图同时抢带宽（115 这类网盘源会直接限流）

列表里的海报 / 背景图格子只有 34×51 和 60×34，直接发原图（单张 100KB～1MB）条目一多就卡，所以列表请求带 `w=96` / `w=144` 取服务端压好的小图：

- 小图按「文件 + 修改时间 + 尺寸」指纹缓存在 `config/thumbs/`，同一张只生成一次；单张 2～4KB，一页 60 条的图片总量从几十兆降到几百 KB
- 源图重新生成后指纹变化，自动换新；缓存 14 天过期、最多 2000 张，几张几十像素的小图不占地方
- 预览弹窗、选帧面板不带 `w`，仍然拿原图，画质不受影响

**怎么更快、又不容易被限流**

每多一个采样帧就多一次网络抓帧（重新建连、重新跳转、重新定位），而网盘源是按瞬时并发掐人的，所以「降帧数」比「提并发」划算得多：

| 做法 | 效果 |
|---|---|
| `scrape.frames: 2`（默认） | 单文件抓帧次数从 5 次降到 2 次，整库快一倍以上；两帧取位置列表两端，撞黑场和片头的概率更低 |
| `scan.timeout: 30`（默认） | 一条抽风的链接最多占 30 秒，不会一个文件卡 4 分钟把队列拖住 |
| 并发保持 `3` | 提到 5 以上不会更快——被限流后所有连接一起慢，反而更慢 |
| 撞到 429 / 503 / 504 自动退避 | 连续命中按 5s → 15s → 45s → 135s → 300s 递增，成功一批后逐步衰减；网页状态徽标会显示「限流退避 Ns」，点「暂停」能立刻中断等待 |
| 想再快 | 把网盘挂成本地目录（alist / rclone / CloudDrive2）让 ffmpeg 读本地文件，随机跳转从 HTTP 换成文件 seek，通常再快 3 倍以上 |

> 选帧依赖 strm 里的地址当时可用。链接失效时面板会明确提示「这一帧抓不下来」，换时间点或先修好链接再试。

## 登录与账号

控制台默认要求登录，账号密码存在 `config/auth.json` 里（加盐哈希，没有明文）。

| 项 | 说明 |
|---|---|
| 默认账号 | `admin` / `admin`，首次启动自动创建 |
| 改账号 | 打开「设置」页最上面的「登录账号」→ 填当前密码 → 改用户名和/或新密码 → 保存 |
| 会话 | 签名 cookie，默认保持 7 天，超时后自动回登录页 |
| 改完的效果 | 所有旧登录立刻失效，当前这个浏览器自动续上 |
| 防爆破 | 同一 IP 连续 5 次失败锁 5 分钟，日志里有记录 |

相关配置：

```yaml
web:
  auth:
    enabled: true          # 关掉就免登录，只建议在内网或反代鉴权后面这么用
    session_hours: 168     # 登录保持时长
    file: /config/auth.json
```

也可以用环境变量临时关掉：`WS_WEB__AUTH__ENABLED=false`。

> 忘记密码：删掉 `config/auth.json` 后重启容器，会重新生成 `admin` / `admin`。这个文件在 `./config` 卷里，删宿主机的 `config/auth.json` 即可。

## 日志与排查

日志三路同时输出，各管一件事：

| 位置 | 内容 | 什么时候看 |
|---|---|---|
| `docker logs strm-scraper` | 实时控制台输出 | 容器刚起来、想看有没有立刻报错 |
| `config/logs/strm-scraper.log` | 全量，5MB 滚动，保留 5 份 | 事后复盘，网页缓冲被刷掉之后 |
| `config/logs/errors-*.log` | 只有 WARNING 及以上 | 只想看异常，不想翻进度 |
| 网页「运行日志」 | 最近 1000 条，可筛选 | 日常用 |

每条日志带时间、级别、来源模块（`worker` / `probe` / `frames` / `mediaserver`）和消息。单条结果长这样：

```
19:45:46 INFO  [worker      ] [完成] 流浪地球2.2023 | 17.1s | 海报 106KB 背景 169KB 缩略图 77KB NFO 1KB
19:45:46 WARNING [mediaserver] 假Emby 回查：1 条仍无海报 …
```

`log.level` 设成 `DEBUG` 能看到每次抓帧、每次请求的细节，排查完记得改回来。

**先跑自检**

```bash
docker exec strm-scraper python -m scraper.main --doctor
```

会依次检查 Python、ffmpeg/ffprobe、扫描目录和 strm 数量、状态库可写性、日志落盘、每台媒体服务器的连通性和鉴权方式，最后汇总问题数量。发现问题会直接说缺什么，比盯着日志猜快得多。

## 常见问题

**忘记密码了**

删掉宿主机的 `config/auth.json`，重启容器，账号恢复成 `admin` / `admin`。刮削进度和已生成的图片都不受影响，只有登录信息重置。

**不想每次登录**

两种做法：`web.auth.enabled: false` 或环境变量 `WS_WEB__AUTH__ENABLED=false`。只建议在内网、或前面有带鉴权的反向代理时这么用——控制台没有登录就等于把刮削按钮开放给所有能访问端口的人。

**登录一直提示密码错误，改过用户名**

用户名不区分大小写（`Admin` 和 `admin` 等价），密码区分。如果连自己改成什么了都忘了，按上一条删 `auth.json` 重置。

**扫描目录为空 / 提示目录不存在**

`scan.roots` 写的是**容器内路径**，不是宿主机路径。宿主机 `/vol1/1000/LitePan/strm` 挂到容器 `/media`，配置里就写 `/media`。

**海报写不进媒体目录**

权限问题。NAS 上的目录通常属于某个用户，容器默认以 root 跑一般没问题；如果挂了 `user:` 字段，要保证那个 uid 对媒体目录有写权限。

**大量「连接超时」或「连接被拒绝」**

strm 里的地址失效了。检查网盘挂载工具是否在跑、内网穿透端口是否正常。这类失败不会拖慢整轮，`probe_timeout` 一到就跳过。

**都显示成功但媒体库里没海报**

先看网页日志里「回查」那条：

- 「N 条全部已有海报」→ 服务端已经识别，客户端刷新一下就好
- 「N 条仍无海报」→ 点面板上的「补齐缺图」，或确认 `path_map` 是否正确
- 图片文件本身不存在 → 看条目产物大小，重刮这一条

Emby 一般会自动发现新图片，Jellyfin 必须显式刷新，这是两家行为差异，不是 bug。

**媒体服务器连不上**

日志会写清楚是哪种情况：`鉴权失败` 说明密钥不对或权限不足；`连不上` 说明地址/端口不通；`SSL 证书校验失败` 时把 `insecure: true` 加上（自签名证书）。网页上点「测试连接」可以立刻复测。

**封面还是同一张**

说明这个视频可选帧之间差别不大，或者采样区间都落在相似场景里。可以调 `scrape.frame_positions` 换采样位置。

**海报里主体被切了**

确认 `scrape.poster.mode` 是 `crop`（默认，画面铺满 2:3）。不喜欢左右被裁可以改成 `blur`（模糊背景 + 完整画面居中）或 `gradient`（纯渐变背景）。

**能只刮某个子目录吗**

把 `scan.roots` 指向那个子目录即可，支持多个目录。

**会不会覆盖我手动改过的 NFO**

默认 `overwrite: missing`，文件存在就跳过。只有设成 `always`、文件管理点「开始重刮」，或任务页点「全量重刮（整库）」才会覆盖。

## 工作原理

```
扫描目录 ──> 读 strm 首行 URL ──> ffprobe 探测（时长/分辨率/码率）
                                        │
                                        ├─> ffmpeg 按比例抓 5 帧 ──> 挑最清晰的一帧
                                        │                          │
                                        │                          ├─> 2:3 海报
                                        │                          ├─> 16:9 背景图
                                        │                          └─> 16:9 缩略图
                                        └─> 写 NFO

状态写进 SQLite，网页读状态库，实现增量与失败重试

刮削完成 ──> 各台 Emby / Jellyfin 刷新图片缓存 ──> 回查确认
```

抓帧只请求视频中间几个时间点的数据，不落盘完整文件。115 直链是 302 跳转到 CDN，播放和抓帧的流量都不经过你自己的网络。

## 本地运行

不用 Docker 也可以，需要 Python 3.10+ 和 ffmpeg：

```bash
pip install -r requirements.txt
python -m scraper.main --config config.yaml
```

本地跑要注意默认路径都是容器里的 `/config`，改成相对路径：

```yaml
storage:
  state_db: ./data/state.db
web:
  auth:
    file: ./data/auth.json
log:
  dir: ./data/logs
```

先跑一条视频确认环境正常：

```bash
python scripts/selftest.py /path/to/影片.strm
```

它会依次检查 ffmpeg、解析 strm、探测、抓帧、出图、写 NFO，哪一步失败会直接告诉你原因。

改完前端或接口想整套验证，用 `tools/` 下的脚本（会自己造测试视频和假媒体库）：

```bash
python tools/devserver.py            # 起一套本地环境，控制台 http://127.0.0.1:6670
python tools/devserver.py --host 0.0.0.0   # 同上，但手机 / 另一台机器也能连（会打印局域网地址）
python tools/selftest_ui.py          # 界面回归：勾选、暂停、选帧、目录树、勾选删除、设置页（支持 --base）
python tools/selftest_auth.py        # 登录 / 改账号：自己起独立环境，跑完自动清理
python tools/check_thumbs.py         # 缩略图接口：小图尺寸、比例、缓存头、越界拦截
python tools/check_list_images.py    # 列表走小图、预览走原图（需要 Edge）
python tools/check_dirview.py        # 目录树：展开/收起滚动不跳、大文件夹不卡（需要 Edge）
python tools/check_sort.py           # 排序 / 老库升级 / 配置写回 / 兜底抓帧（纯逻辑，秒级）
python tools/check_sort_ui.py        # 排序控件与列表顺序（需要 Edge）
python tools/check_sort_race.py      # 页面刚加载就点排序，不能被旧响应盖回去（需要 Edge）
python tools/check_file_state.py     # 文件管理状态列：按产物判定刮削成功 / 未刮削（需要 Edge）
python tools/check_folder_poster.py  # 多层文件夹的封面提示、手动修复、指定用哪张（需要 Edge）
python tools/check_poster_status.py  # 海报未生成：进度条、明细、只看未生成（需要 Edge，自带素材）
python tools/check_scan.py           # 扫描提速：新旧实现结果一致 + 提速倍数
```

想拿自己的真实素材（比如从 115 导出的 strm 目录）验收，不用改配置：

```bash
python tools/devserver.py --media-root "D:/Desktop/test strm" --data .devdata_real
python tools/check_real_ui.py        # 按这套素材跑：勾文件夹、齐全跳过、开始重刮、删除、拖框裁切
```

`--media-root` 只把扫描根指过去，不会生成或删除素材目录里的东西；`--data` 把状态库、日志另放一处，跟默认环境互不干扰。加 `--reset` 会清掉上一轮生成的图片和 NFO（`.strm` 不动）。
